# 11. 앱 직접 빌드하기 (DODA 가 자기 계정으로)

[English](#english) · 한국어

이 안내서를 따르면 **DODA 가 개발사 없이** 고객 앱·파트너 앱을 직접 빌드해서 DODA 의 Google Play 와 App Store Connect 에 올릴 수 있어요.
개발사에 초대장을 보내거나, 도메인·키를 개발사에 넘길 필요가 없어요. 빌드는 Codemagic 클라우드에서 해요. 맥이나 개발 도구는 필요 없어요.

> 이 안내서가 가리키는 파일: [codemagic.yaml](../../codemagic.yaml) (빌드 설정), [scripts/ci/native-keys.sh](../../scripts/ci/native-keys.sh) (키 변수), [LICENSE](../../LICENSE) (사용 조건). 스토어 문구는 [store/](../store/) 에 있어요.

## 0. 시작 전에 확인할 것

- **라이선스가 먼저예요.** 저장소의 `LICENSE` 1.4 조와 3.1 조는 포크(복제)만으로는 사용 권한이 생기지 않는다고 해요. 사용하려면 저작권자(Eric Wijesinghe)와 **서면 라이선스 계약**을 맺어야 해요. 확인 필요: 계약 체결 여부와 포크 허용 범위. 계약 없이 진행하지 마세요.
- **저장소는 공개예요.** 포크도 공개가 돼요. 키, 비밀번호, `.p8` 파일, keystore 는 저장소에 올리지 마세요. 모든 키는 Codemagic 에만 넣어요.

## 1. 저장소 포크

1. https://github.com/EricWijesinghe/Dahae 를 열고 오른쪽 위 **Fork** → Owner 를 DODA 계정으로 고르기 → **Create fork**.
2. 포크의 **Settings → Secrets and variables → Actions** 에는 아무것도 넣지 마세요.
3. 포크의 **Actions** 탭에서 `release` 와 `deploy-aws` 워크플로를 열고 **…** → **Disable workflow**. 이유: 두 워크플로는 개발사의 서명 키와 AWS 설정을 써요. DODA 포크에는 없으니 실패하거나 엉뚱한 곳으로 배포를 시도해요. 확인 필요: 메뉴 이름이 다를 수 있어요.
4. 버전 태그: 포크의 **Releases → Draft a new release** → **Choose a tag** 에 `v1.5.1` 입력 → **Create new tag: v1.5.1 on publish** → Target `master` → **Publish release**. 태그 이름은 `v1.2.3` 모양이어야 해요. 태그가 없으면 Codemagic 이 `pubspec.yaml` 의 버전 (1.5.1) 을 써요.

## 2. Codemagic 가입과 앱 추가

1. https://codemagic.io 에서 **Sign up** → **GitHub** 로 DODA 계정 가입.
2. **Add application** → **GitHub** → 포크 `Dahae` 선택 → 설정 방식은 **codemagic.yaml** (저장소 맨 위 파일) → **Finish**.
3. Codemagic 이 GitHub 저장소 접근을 물으면 **Authorize** 하세요.
4. `codemagic.yaml` 이 고정해 둔 버전: Flutter **3.47.9**, Xcode **26.6**. 이 버전을 Codemagic 이 제공하지 않으면 첫 빌드 로그에 나와요. 확인 필요.

## 3. Codemagic 설정 (이름과 값을 정확히 그대로)

`codemagic.yaml` 이 읽는 이름이에요. 옛 프로젝트 이름 `malkkeum` 이 들어 있어요. **바꾸지 말고 그대로 입력하세요.** 바꾸면 빌드가 실패해요.

### 3-1. App Store Connect 연결 (이름 `malkkeum_asc`)

1. Codemagic → **Teams** → **Integrations** → **App Store Connect** → **Add key** (또는 +).
2. **Name**: `malkkeum_asc`
3. **Issuer ID**, **Key ID**, **.p8 파일** 을 넣어요. 값은 [4-2](#4-2-app-store-connect-앱과-api-키)에서 받아요.

### 3-2. Android 업로드 키 (참조 이름 `malkkeum_upload`)

업로드 키는 DODA 가 만드는 DODA 자신의 키예요. 개발사의 키를 받지 않아요.

1. PC 에 Java 의 `keytool` 이 있어야 해요 (확인 필요: 없으면 JDK 설치). 명령 프롬프트에서 한 번 실행:

   ```
   keytool -genkeypair -v -keystore dahae-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
   ```

   비밀번호 두 번과 이름 칸을 물어봐요. 저장소 비밀번호와 키 비밀번호는 같게 두는 것을 권해요. 파일 `dahae-upload.jks` 가 만들어져요.
2. Codemagic → **Code signing identities** → **Android keystores** → **Upload keystore** (확인 필요: 메뉴 이름).
3. 파일 `dahae-upload.jks` 선택, **Keystore password**, **Key alias** `upload`, **Key password** 입력.
4. **Reference name**: `malkkeum_upload` → **Save**.
5. **백업 (꼭 하세요):** `dahae-upload.jks` 파일과 비밀번호, alias `upload` 를 서로 다른 두 곳 (USB, 비밀번호 관리자) 에 보관하세요. 잃으면 Play 업데이트를 못 해요. 복구는 Play 지원팀을 통해서만 가능해요 (확인 필요: 절차). 저장소나 메일에 올리지 마세요.

Play App Signing 은 Play Console 이 앱 서명 키를 따로 보관해요. 이 업로드 키는 "업로드 키"예요.

### 3-3. 환경 변수 그룹 `malkkeum`

1. Codemagic → **Environment variables** → **Add group** → 이름 `malkkeum`.
2. 아래 변수를 넣고, **모든 값에 Secure (비밀) 체크**.

| 변수 이름 | 넣을 값 | 없으면 |
|---|---|---|
| `API_BASE` | `https://<DODA 도메인>` (예: `https://myshop.co.kr`) | **필수.** 없으면 앱이 실행되지 않아요 |
| `GCLOUD_SERVICE_ACCOUNT_CREDENTIALS` | Play 서비스 계정 JSON 파일의 내용 전체 ([4-3](#4-3-google-play-console-과-서비스-계정)) | Play 자동 업로드가 안 돼요 (5번 참고) |
| `KAKAO_NATIVE_KEY` | 카카오 네이티브 앱 키 ([4-5](#4-5-kakao-developers-선택)) | 카카오 로그인 버튼이 숨겨져요 |
| `NAVER_CLIENT_ID` | 네이버 Client ID ([4-6](#4-6-naver-developers-선택)) | 네이버 버튼이 숨겨져요 (`APP_LINK_DOMAIN` 도 필요) |
| `NAVER_CLIENT_SECRET` | **넣지 마세요.** 앱이 쓰지 않아요 (아래 참고) | — |
| `NAVER_CLIENT_NAME` | 비워 두세요 (확인 필요: 앱이 읽는지) | — |
| `GOOGLE_SERVER_CLIENT_ID` | 구글 **Web** OAuth 클라이언트 ID ([4-7](#4-7-google-oauth-선택)) | 구글 로그인 버튼이 숨겨져요 |
| `GOOGLE_IOS_CLIENT_ID` | 구글 **iOS** OAuth 클라이언트 ID ([4-7](#4-7-google-oauth-선택)) | iOS 구글 로그인이 꺼져요 |
| `SOCIAL_PROVIDERS` | 보통 비워 둠. 예: `kakao,naver` | 전부 켜져요 |
| `APP_LINK_DOMAIN` | 도메인만 (예: `myshop.co.kr`). `https://`, `/` 없이 | 네이버 로그인이 숨겨져요 |
| `GOOGLE_SERVICES_JSON_B64` | 고객 Android `google-services.json` 을 base64 한 줄로 ([4-4](#4-4-firebase-푸시)) | 고객 앱 푸시가 꺼져요 |
| `GOOGLE_SERVICE_INFO_PLIST_B64` | 고객 iOS `GoogleService-Info.plist` 를 base64 한 줄로 | 고객 iOS 푸시가 꺼져요 |
| `PARTNER_GOOGLE_SERVICES_JSON_B64` | 파트너 Android `google-services.json` base64 | 아래 참고 |
| `PARTNER_GOOGLE_SERVICE_INFO_PLIST_B64` | 파트너 iOS `GoogleService-Info.plist` base64 | 아래 참고 |

**꼭 알아 둘 것**
- **Firebase 네 개는 전부 넣거나 전부 비우세요.** 파트너 값이 없으면 스크립트가 고객 값을 대신 써요 (`native-keys.sh` 읽기 기준, 확인 필요). 그러면 파트너 앱 ID 와 맞지 않아 빌드가 실패할 수 있어요.
- **`NAVER_CLIENT_SECRET` 은 Codemagic 에 넣지 마세요.** [DEPLOY §3](../DEPLOY.md) 은 이 값이 서버에만 있다고 하지만, `native-keys.sh` 는 이 변수가 있으면 앱 설정 파일 `keys.json` 에 넣어요 (확인 필요). 앱은 이 값을 읽지 않아요. 네이버 시크릿은 [4-6](#4-6-naver-developers-선택)처럼 서버 콘솔에만 넣어요.
- **base64 만드는 법** (Google 파일을 한 줄 문자열로):
  - Windows (PowerShell): `[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\경로\google-services.json"))`
  - Mac / Linux (터미널): `base64 < google-services.json | tr -d '\n'`
  - 결과를 그대로 Codemagic 값 칸에 붙여넣어요. base64 는 암호화가 아니니 **Secure 체크**를 꼭 하세요.

### 3-4. 저장

그룹을 **Save** 한 뒤 변수 목록을 한 번 다시 보세요. 이름 철자가 하나라도 다르면 그 값은 조용히 무시돼요 (빌드는 성공해도 버튼이 숨겨져요).

## 4. 스토어와 서비스에 먼저 만들 것

순서대로 하세요. 앱 ID 두 개는 한 번 정하면 바꿀 수 없어요: 고객 `kr.co.dahae.customer`, 파트너 `kr.co.dahae.partner` ([REBRAND-CHECKLIST](../REBRAND-CHECKLIST.md) §3).

### 4-1. Apple App ID 와 APNs 키

1. developer.apple.com → **Account** → **Membership details** → **Team ID** (10자리) 복사. 나중에 [4-8](#4-8-도메인-서버-앱-링크-첫-aab-업로드-뒤)에 써요.
2. **Certificates, Identifiers & Profiles → Identifiers → +** → **App IDs** → **App**.
   - Description: `Dahae Customer` (또는 파트너)
   - Bundle ID (**Explicit**): `kr.co.dahae.customer` (파트너는 `kr.co.dahae.partner`)
   - Capabilities 에서 **Push Notifications**, **Sign in with Apple**, **Associated Domains** 세 개를 모두 체크 → **Continue** → **Register**. 하나라도 빠지면 Codemagic 서명이 실패해요.
3. **Certificates, Identifiers & Profiles → Keys → +** → **Apple Push Notifications service (APNs)** 체크 → **Continue** → **Register** → `.p8` 다운로드 (한 번만 받을 수 있어요). Key ID 를 적어 두세요. [4-4](#4-4-firebase-푸시)에서 Firebase 에 올려요.

### 4-2. App Store Connect 앱과 API 키

1. appstoreconnect.apple.com → **Apps → +** → **New App**, 앱마다 한 번씩:
   - Platforms: iOS, Name: `다해` (파트너는 `다해 파트너`), Primary Language: Korean, Bundle ID: 위에서 만든 ID 선택, SKU: 자유 (예: `dahae-customer`) → **Create**.
2. **Users and Access → Integrations → App Store Connect API → Team Keys → +**
   - Name 은 자유, Access: **App Manager** → **Generate**.
   - `.p8` 다운로드 (한 번만), **Issuer ID** 와 **Key ID** 를 복사.
3. 이 세 값을 [3-1](#3-1-app-store-connect-연결-이름-malkkeum_asc) 에 넣어요.

### 4-3. Google Play Console 과 서비스 계정

1. play.google.com/console → **계정 만들기 → 조직** → D-U-N-S 번호, 등록비 결제, 신원 확인 ([guide 03](03-앱-출시.md) B). 승인까지 며칠 걸려요.
2. **앱 만들기** 두 번: `다해` (고객), `다해 파트너` (파트너). 기본 언어 한국어, 앱, 무료. 패키지 이름(`kr.co.dahae.customer` 등)은 첫 AAB 를 올릴 때 정해져요 (확인 필요).
3. **서비스 계정 키 만들기** (Google Cloud Console, 같은 Google 계정):
   - 프로젝트 선택 또는 새로 만들기 → **IAM 및 관리자 → 서비스 계정 → 서비스 계정 만들기** → 이름 입력 → 역할은 비워도 돼요 (확인 필요).
   - 만든 계정 클릭 → **키 → 키 추가 → 새 키 만들기 → JSON** → 다운로드.
4. **Play Console → 설정 → API 액세스** (확인 필요: 메뉴 이름): 위 Google Cloud 프로젝트를 연결 → 서비스 계정 옆 **액세스 권한 부여** → 권한 **출시 관리자 (Release manager)** → 두 앱 모두 선택 → 초대.
5. JSON 파일의 **내용 전체**를 [3-3](#3-3-환경-변수-그룹-malkkeum) 의 `GCLOUD_SERVICE_ACCOUNT_CREDENTIALS` 에 붙여넣어요.

### 4-4. Firebase (푸시)

1. console.firebase.google.com → **프로젝트 추가** (DODA 계정).
2. **프로젝트 설정 → 앱 추가**:
   - Android: 패키지 이름 `kr.co.dahae.customer` → `google-services.json` 다운로드 → base64 → 변수 `GOOGLE_SERVICES_JSON_B64`.
   - Android: 패키지 `kr.co.dahae.partner` → 같은 방법 → `PARTNER_GOOGLE_SERVICES_JSON_B64`.
   - iOS: 번들 ID `kr.co.dahae.customer` → `GoogleService-Info.plist` → `GOOGLE_SERVICE_INFO_PLIST_B64`. 파트너 iOS 도 같은 방법 → `PARTNER_GOOGLE_SERVICE_INFO_PLIST_B64`.
3. **프로젝트 설정 → Cloud Messaging → Apple 앱 구성**: 각 iOS 앱에 [4-1](#4-1-apple-app-id-와-apns-키)의 `.p8` 파일, Key ID, Team ID 를 올려요.
4. **서버용 키 (푸시 발송):** 프로젝트 설정 → **서비스 계정 → 새 비공개 키 생성** → JSON. 이 파일은 Codemagic 이 아니라 **서버 콘솔 설정의 Firebase (Push) 카드**에 넣어요 ([DEPLOY §3](../DEPLOY.md)).

### 4-5. Kakao Developers (선택)

1. developers.kakao.com → **내 애플리케이션 → 애플리케이션 추가** (이름 `다해`).
2. **앱 키 → 네이티브 앱 키** → `KAKAO_NATIVE_KEY` 에 넣어요.
3. **플랫폼**: Android 패키지 이름 `kr.co.dahae.customer`, `kr.co.dahae.partner` 와 **키 해시** (Play 앱 서명 SHA-1 을 base64 로 바꾼 값. [4-8](#4-8-도메인-서버-앱-링크-첫-aab-업로드-뒤) 뒤에 가능), iOS 번들 ID 두 개. 확인 필요: 두 앱을 한 카카오 앱에 같이 등록하는지 (변수가 하나라서 그렇게 보여요).
4. 앱 ID (숫자), REST API 키 → **서버 콘솔의 Kakao 카드** ([guide 02](02-설정-마법사.md) 표).

### 4-6. Naver Developers (선택)

1. developers.naver.com → **애플리케이션 등록** → 사용 API **네이버 로그인**.
2. **서비스 URL**: `https://<DODA 도메인>`, **Callback URL**: `https://<DODA 도메인>/auth/naver/callback`.
3. Android 패키지 이름, iOS 번들 ID, iOS URL 스킴 `dahaenaver` ([DEPLOY §3](../DEPLOY.md) 의 호환 항목).
4. **Client ID** → `NAVER_CLIENT_ID`. **Client Secret** → **서버 콘솔의 Naver 카드**에만 넣어요.

### 4-7. Google OAuth (선택)

Google Cloud Console → **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**:
- **웹 애플리케이션** → 클라이언트 ID → `GOOGLE_SERVER_CLIENT_ID`. 같은 값을 서버 콘솔의 Google 카드에도 넣어요.
- **iOS** → 번들 ID `kr.co.dahae.customer` → 클라이언트 ID → `GOOGLE_IOS_CLIENT_ID`.
- **Android** 클라이언트: 패키지 이름과 **Play 앱 서명 SHA-1** 이 필요해요 ([4-8](#4-8-도메인-서버-앱-링크-첫-aab-업로드-뒤) 뒤에 가능, [LAUNCH-PLAN](../LAUNCH-PLAN.md) §2).
- 확인 필요: [DEPLOY §3](../DEPLOY.md) 은 iOS 클라이언트를 "번들 ID 마다" 만들라고 하지만, `native-keys.sh` 는 `GOOGLE_IOS_CLIENT_ID` 한 개만 받아요. 파트너 iOS 구글 로그인이 맞게 되는지 첫 빌드 뒤 확인하세요.

### 4-8. 도메인, 서버, 앱 링크 (첫 AAB 업로드 뒤)

1. 서버를 올려요: [guide 00](00-한번에-설치.md) / [guide 08](08-클라우드-배포.md) / [guide 10](10-AWS-배포.md). 도메인이 `API_BASE` 와 `APP_LINK_DOMAIN` 이 돼요.
2. 첫 Play 업로드 (6번) 뒤: **Play Console → 릴리스 → 앱 무결성 (App integrity)** → **앱 서명 키 인증서의 SHA-256** 과 **SHA-1** 복사 (확인 필요: 메뉴 이름).
3. **서버 콘솔 → 설정 → 앱 링크** 카드: 안드로이드 SHA-256 (여러 개면 쉼표), **Apple Team ID** ([4-1](#4-1-apple-app-id-와-apns-키) 1번). 확인 후 저장. 저장한 값이 서버 설정보다 우선해요 ([DEPLOY §3](../DEPLOY.md)). 서버 터미널 명령 `dahae applinks` 는 필요 없어요.
4. 계정 삭제 때 Apple 토큰을 지우려면 콘솔 **Apple 카드**에 Sign in with Apple 키 (`.p8`, Key ID, Team ID) 를 넣어요 (권장, [DEPLOY §4](../DEPLOY.md)).
5. 브라우저에서 열어 확인: `https://<도메인>/.well-known/assetlinks.json` 과 `https://<도메인>/.well-known/apple-app-site-association` 이 글자(JSON)로 보여야 해요.
6. 키를 나중에 넣었으면 (카카오, 구글, 네이버) 빌드를 다시 해요. 약 1시간 걸려요 ([LAUNCH-PLAN](../LAUNCH-PLAN.md) §2).

## 5. 빌드 네 개 실행

1. Codemagic → 앱 **Dahae** → **Start new build** → 워크플로 선택 → **Tag** `v1.5.1` (또는 Branch `master`).
2. 이 순서로 실행해요: `customer-android` → `partner-android` → `customer-ios` → `partner-ios`. Android 가 먼저 끝나면 키와 서명이 맞는지 빨리 알 수 있어요. 빌드 제한 시간은 Android 60분, iOS 90분이에요.
3. 성공 확인: 빌드 로그의 마지막 쪽에 `check-native` 단계가 통과해야 해요.
4. **결과 받기**: 빌드 페이지 → **Artifacts**:
   - Android: `app-release.aab` (Play 업로드용), `mapping.txt`, `*.symbols` (충돌 분석용. 보관하세요).
   - iOS: `*.ipa`, `*.dSYM` (보관하세요).
5. **자동 업로드**:
   - Android: `GCLOUD_SERVICE_ACCOUNT_CREDENTIALS` 가 있으면 Play **내부 테스트 트랙에 초안 (draft)** 으로 올라가요.
   - iOS: App Store Connect 에 올라가고 TestFlight 로 가요. 처리에 10–30분 걸려요.
   - **`GCLOUD_SERVICE_ACCOUNT_CREDENTIALS` 가 없으면:** 확인 필요. 이 저장소에서는 Codemagic 이 빈 값을 어떻게 처리하는지 알 수 없어요. 빌드 페이지에 **publishing 단계가 실패**로 보일 수 있어요. 그래도 AAB 는 Artifacts 에 남아요. 내려받아서 6번처럼 직접 올리면 돼요.

## 6. Play 첫 업로드 (직접, 앱마다 한 번)

Google Play 의 API 로는 첫 릴리스를 만들 수 없어요. 첫 번째만 사람이 올려요.

1. Play Console → 앱 (`다해`) → **테스트 및 출시 → 내부 테스트 → 새 버전 만들기** → **App Bundle 업로드** → Artifacts 의 `app-release.aab` 선택.
2. Play App Signing 안내가 나오면 **계속** (기본값으로 켜 두세요).
3. 출시 전에 채워야 할 것 (심사가 아니어도 출시 버튼이 막혀요):
   - **앱 콘텐츠**: [play-declarations.md](../store/play-declarations.md) 답변, 데이터 보안: [data-safety.md](../store/data-safety.md)
   - **스토어 등록정보**: [listing-ko.md](../store/listing-ko.md), [listing-en.md](../store/listing-en.md) 문구, 스크린샷 (아래 참고)
   - 개인정보처리방침 `https://<도메인>/privacy.html`, 계정 삭제 `https://<도메인>/delete-account.html` ([guide 03](03-앱-출시.md) D)
   - 내부 테스터 이메일 목록 (확인 필요)
4. 파트너 앱도 같은 순서로 해요.
5. 첫 업로드 뒤 [4-8](#4-8-도메인-서버-앱-링크-첫-aab-업로드-뒤)의 SHA 값을 옮겨요.
6. 이후 Codemagic 이 올리는 초안은 Play Console 에서 확인한 뒤 **출시 (승격)** 하면 돼요.

**스크린샷:** 저장소의 `docs/store/screenshots/` 에 이미 있어요. 이름을 바꾸기 전에 만든 사진이면 다시 만들어야 해요 ([REBRAND-CHECKLIST](../REBRAND-CHECKLIST.md) §3). 다시 만들 때는 `scripts/store/generate.sh`. 확인 필요: 저장소 Release `v1.5.1` 의 `dahae-store-images-1.5.1.zip` 첨부 여부 (소유자가 첨부 예정).

## 7. iOS: TestFlight 와 심사 제출

1. App Store Connect → 앱 → **TestFlight** → 빌드가 **처리 중 → 완료** 될 때까지 10–30분 기다리세요.
2. 암호화 질문이 나오면 [app-privacy.md](../store/app-privacy.md) 의 수출 규정 답변대로 답해요 (확인 필요).
3. **내부 테스트**: TestFlight → 내부 테스트 그룹 → DODA 직원 추가 → TestFlight 앱에서 설치 → 로그인, 사진, 결제 창, 푸시, 위치를 실기기에서 확인 ([ios-release.md](../store/ios-release.md) §2).
4. **심사 제출 (사람이 직접 해요.** Codemagic 은 심사에 보내지 않아요):
   - App Store Connect → 앱 → **iOS 앱 → +** → 버전 번호 (예: 1.5.1) → **빌드** 에서 방금 올라온 빌드 선택.
   - **App 심사 정보 → 메모**: [review-notes.md](../store/review-notes.md) 내용 붙여넣기.
   - **데모 계정**: [guide 03](03-앱-출시.md) D 대로 서버 콘솔에서 켜기 (확인 필요: 심사 직전에).
   - **App 개인정보 보호**: [app-privacy.md](../store/app-privacy.md) 대로 입력.
   - **심사에 추가 → 심사 제출**. 두 앱 모두 따로 해요.

## 8. 업데이트

1. 새 버전: 포크에서 새 태그 (예: `v1.5.2`) 를 Release 로 만들고, Codemagic 에서 네 개 워크플로를 다시 실행해요. 빌드 번호는 자동으로 올라가요 ([scripts/ci/build-number.py](../../scripts/ci/build-number.py)). 직접 정하지 마세요.

## English

This guide lets DODA build the customer and partner apps **without the developer**, and upload them to DODA's own Google Play Console and App Store Connect. Builds run on Codemagic (cloud Macs). No Mac or developer tools are needed. DODA sends nothing to the developer: no invitations, no domain, no keys.

### 0. Before you start

- **License first.** `LICENSE` sections 1.4 and 3.1 say forking or cloning does not grant any right to use the software. You need a **written license agreement** with the copyright holder (Eric Wijesinghe). Confirm with the owner before you begin. (To be confirmed: whether that agreement exists and what the fork may be used for.)
- **The repository is public.** Forks are public too. Never commit keys, passwords, `.p8` files or keystores. Put every secret into Codemagic only.

### Accounts you need

GitHub (DODA), Codemagic, Apple Developer Program as an **organization** (annual fee 99 USD, D-U-N-S number), Google Play Console as an **organization** (registration fee 25 USD per [guide 03](03-앱-출시.md), to be confirmed; D-U-N-S number), Firebase, and optionally Kakao, Naver and Google Cloud. Costs and Codemagic pricing: to be confirmed.

### 1. Fork the repository

1. Open https://github.com/EricWijesinghe/Dahae → **Fork** → choose DODA as owner → **Create fork**.
2. Add no secrets to the fork.
3. **Actions** tab: disable `release` and `deploy-aws` (**…** → **Disable workflow**). They need the developer's signing and AWS settings. To be confirmed: the menu label.
4. Tag: **Releases → Draft a new release** → tag `v1.5.1` (create on publish, target `master`) → **Publish release**. The tag must look like `v1.2.3`. Without a tag, Codemagic uses the version in `pubspec.yaml` (1.5.1).

### 2. Connect Codemagic

1. codemagic.io → **Sign up** with GitHub.
2. **Add application** → GitHub → select the fork `Dahae` → choose the **codemagic.yaml** setup → **Finish**. Authorize the GitHub access it asks for.
3. `codemagic.yaml` pins **Flutter 3.47.9** and **Xcode 26.6**. If Codemagic does not offer these, the first build log shows it (to be confirmed).

### 3. Codemagic settings: use these exact names

The file reads these names. The old project name `malkkeum` is in them on purpose. **Do not rename them**, or the builds fail.

**3-1. App Store Connect integration, name `malkkeum_asc`.** Teams → Integrations → App Store Connect → Add key. Name `malkkeum_asc`, the **Issuer ID**, the **Key ID** and the `.p8` file (from step 4-2).

**3-2. Android upload keystore, reference name `malkkeum_upload`.** DODA makes its own key. Run once, with Java's `keytool` (install a JDK if needed; to be confirmed):

```
keytool -genkeypair -v -keystore dahae-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

Codemagic → **Code signing identities → Android keystores → Upload keystore** (menu label to be confirmed). Choose `dahae-upload.jks`, enter the keystore password, alias `upload` and the key password. Reference name **`malkkeum_upload`**. **Back it up** in two separate places (USB and a password manager). If it is lost, Play updates are blocked until Play support resets the upload key (to be confirmed).

**3-3. Environment variable group, name `malkkeum`.** Codemagic → Environment variables → Add group. Mark every value **Secure**.

| Variable | Value | If missing |
|---|---|---|
| `API_BASE` | `https://<DODA domain>` | **Required.** The release app will not start |
| `GCLOUD_SERVICE_ACCOUNT_CREDENTIALS` | the whole Play service-account JSON (step 4-3) | no automatic Play upload (see step 5) |
| `KAKAO_NATIVE_KEY` | Kakao native app key | Kakao button hidden |
| `NAVER_CLIENT_ID` | Naver Client ID | Naver button hidden (also needs `APP_LINK_DOMAIN`) |
| `NAVER_CLIENT_SECRET` | **Leave empty.** The app does not read it; the secret goes into the server console | — |
| `NAVER_CLIENT_NAME` | leave empty (to be confirmed) | — |
| `GOOGLE_SERVER_CLIENT_ID` | Google **Web** OAuth client ID | Google button hidden |
| `GOOGLE_IOS_CLIENT_ID` | Google **iOS** OAuth client ID | iOS Google sign-in off |
| `SOCIAL_PROVIDERS` | usually empty (e.g. `kakao,naver`) | all providers on |
| `APP_LINK_DOMAIN` | bare domain, e.g. `myshop.co.kr` (no `https://`, no `/`) | Naver sign-in hidden |
| `GOOGLE_SERVICES_JSON_B64` | customer Android `google-services.json` as one base64 line | customer push off |
| `GOOGLE_SERVICE_INFO_PLIST_B64` | customer iOS `GoogleService-Info.plist` as base64 | customer iOS push off |
| `PARTNER_GOOGLE_SERVICES_JSON_B64` | partner Android file, base64 | see below |
| `PARTNER_GOOGLE_SERVICE_INFO_PLIST_B64` | partner iOS file, base64 | see below |

- Set all four Firebase variables, or none. If the partner value is missing, the script uses the customer value (to be confirmed), which can break the partner build.
- Base64 for Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\path\google-services.json"))`. Mac or Linux: `base64 < google-services.json | tr -d '\n'`. Base64 is not encryption, so keep the Secure flag on.

**3-4.** Save the group, then check every name again. A misspelled name is silently ignored.

### 4. Create these first

Order matters. The app IDs can never be changed after the first upload: customer `kr.co.dahae.customer`, partner `kr.co.dahae.partner`.

**4-1. Apple App IDs and APNs key.** developer.apple.com → Account → Membership details → copy the **Team ID**. Identifiers → **+** → App IDs → App. Explicit bundle IDs `kr.co.dahae.customer` and `kr.co.dahae.partner`. Tick **Push Notifications**, **Sign in with Apple** and **Associated Domains** on both. Keys → **+** → tick **Apple Push Notifications service (APNs)** → download the `.p8` (once only) and note the Key ID.

**4-2. App Store Connect apps and API key.** appstoreconnect.apple.com → Apps → **+** → New App, twice (iOS, Korean, the bundle IDs above, any SKU). Users and Access → Integrations → App Store Connect API → Team Keys → **+** → role **App Manager** → Generate. Download the `.p8` (once), copy the **Issuer ID** and **Key ID**. Enter them in step 3-1.

**4-3. Google Play Console and service account.** Register as an **organization** (D-U-N-S, fee, identity check; days to approve). Create two apps (`다해` and `다해 파트너`, Korean, free). The package name is set by the first AAB upload (to be confirmed). Google Cloud Console → IAM & Admin → Service Accounts → create (no role needed, to be confirmed) → Keys → Add key → Create new key → **JSON**. Play Console → Setup → **API access** (to be confirmed): link the project, **Grant access** to the service account with **Release manager** on both apps. Paste the JSON text into `GCLOUD_SERVICE_ACCOUNT_CREDENTIALS`. (DEPLOY §3 says "Release"; to be confirmed.)

**4-4. Firebase (push).** console.firebase.google.com → add a project. Add Android apps `kr.co.dahae.customer` and `kr.co.dahae.partner`, and iOS apps with the same bundle IDs. Download each file and paste its base64 into the matching variable. In Project settings → Cloud Messaging → Apple app configuration, upload the APNs `.p8` with Key ID and Team ID to each iOS app. For the **server**, create a private key under Service accounts (JSON) and paste it into the server console's **Firebase (Push)** card, not into Codemagic.

**4-5. Kakao (optional).** developers.kakao.com → add app `다해` → App keys → native key → `KAKAO_NATIVE_KEY`. Platforms: Android package names, the key hash (Play app-signing SHA-1 as base64, after step 4-8), iOS bundle IDs (to be confirmed: both apps in one Kakao app). App ID and REST key go into the server console's Kakao card ([guide 02](02-설정-마법사.md)).

**4-6. Naver (optional).** developers.naver.com → register an app with **Naver Login**. Service URL `https://<domain>`, callback URL `https://<domain>/auth/naver/callback`. Client ID → `NAVER_CLIENT_ID`. Client Secret → server console Naver card only.

**4-7. Google OAuth (optional).** Google Cloud Console → Credentials → OAuth client ID: **Web** → `GOOGLE_SERVER_CLIENT_ID` (also in the server console Google card); **iOS** for bundle `kr.co.dahae.customer` → `GOOGLE_IOS_CLIENT_ID`; **Android** needs the Play app-signing SHA-1 (after step 4-8). To be confirmed: DEPLOY §3 says one iOS client per bundle ID, but the script takes one `GOOGLE_IOS_CLIENT_ID`. Check partner iOS Google sign-in after the first build.

**4-8. Domain, server and app links (after the first AAB upload).**
1. Install the server: [guide 00](00-한번에-설치.md), [guide 08](08-클라우드-배포.md) or [guide 10](10-AWS-배포.md). Its domain is `API_BASE` and `APP_LINK_DOMAIN`.
2. In Play Console → Release → **App integrity**: copy the **app signing key certificate SHA-256** (and SHA-1) (menu to be confirmed).
3. Server console → **Settings → App links** card: Android SHA-256 (comma-separated) and the **Apple Team ID**. Save. Saved values override the server settings ([DEPLOY §3](../DEPLOY.md)). The terminal command `dahae applinks` is not needed.
4. Optional but recommended: add the Sign in with Apple key (`.p8`, Key ID, Team ID) in the console's Apple card, for account deletion ([DEPLOY §4](../DEPLOY.md)).
5. Open `https://<domain>/.well-known/assetlinks.json` and `https://<domain>/.well-known/apple-app-site-association` in a browser. Both must show JSON.
6. After adding any key later (Kakao, Google, Naver), run the four builds again (about one hour, [LAUNCH-PLAN](../LAUNCH-PLAN.md) §2).

### 5. Run the four builds

1. Codemagic → app **Dahae** → **Start new build** → pick the workflow → **Tag** `v1.5.1` (or branch `master`).
2. Run in this order: `customer-android`, `partner-android`, `customer-ios`, `partner-ios`. Time limits: 60 minutes (Android), 90 minutes (iOS).
3. Success: the log's last steps include `check-native`.
4. **Artifacts**: Android `app-release.aab` (for Play), `mapping.txt`, `*.symbols` (keep these for crash reports). iOS `*.ipa` and `*.dSYM` (keep).
5. **Automatic upload.** Android goes to the Play internal track as a **draft** if `GCLOUD_SERVICE_ACCOUNT_CREDENTIALS` is set. iOS goes to TestFlight; processing takes 10–30 minutes. **If the Play credential is missing:** to be confirmed. This repository does not show how Codemagic treats an empty value, and the build page may show the publishing step as failed. The AAB is still in Artifacts; download it and upload it yourself (step 6).

### 6. First Play upload (by hand, once per app)

The Google Play API cannot create the first release, so a person uploads the first AAB.

1. Play Console → app → **Testing → Internal testing → Create new release → Upload** `app-release.aab`. Accept **Play App Signing** (default).
2. ### 7. iOS: TestFlight and review

1. App Store Connect → app → **TestFlight**: wait for processing (10–30 minutes).
2. Answer export-compliance questions as in [app-privacy.md](../store/app-privacy.md) (to be confirmed).
3. Internal testing: add DODA staff to an internal group, install with the TestFlight app, and check sign-in, photos, payment window, push and location on a real phone ([ios-release.md](../store/ios-release.md) §2).
4. **Submit by hand.** Codemagic never submits to review. App Store Connect → iOS app → **+** → version number → choose the build. Paste [review-notes.md](../store/review-notes.md) into the review notes. Turn on the demo account (to be confirmed: just before submission; [guide 03](03-앱-출시.md) D). Fill in App Privacy from [app-privacy.md](../store/app-privacy.md). **Submit for Review**. Do both apps.

### 8. Updates

1. New version: create a new tag on the fork (e.g. `v1.5.2`) and run the four workflows again. Build numbers rise automatically ([build-number.py](../../scripts/ci/build-number.py)). Never set them by hand.
2. When the developer sends new code: **Sync fork** on the fork's main page (to be confirmed under the license agreement).
3. Keep the same upload key (`malkkeum_upload`) forever.

### 9. Troubleshooting

| Symptom | Fix |
|---|---|
| `API_BASE must be set to https://...` | Add `API_BASE` with `https://` (step 3-3) |
| `APP_LINK_DOMAIN must be a bare host name` | Remove `https://` and `/` |
| `CM_KEYSTORE_PATH is unset on Codemagic` | Reference name must be `malkkeum_upload` (step 3-2) |
| App Store Connect integration error | Name must be `malkkeum_asc` (step 3-1) |
| iOS signing fails | One of Push, Sign in with Apple, Associated Domains is missing on an App ID (step 4-1) |
| Firebase-related failure | Customer and partner Firebase values do not match (see step 3-3) |
| `Tag ... must look like v1.2.3` | Use a tag such as `v1.5.1` |
| Flutter or Xcode version not found | To be confirmed: whether Codemagic offers 3.47.9 and 26.6 |
