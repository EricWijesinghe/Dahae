# 05. 도메인 연결하고 확인하기

## 이 장에서 할 일

고객이 도메인(예: `example.co.kr`)을 입력하면 4장에서 만든 서버로 오도록 **A 레코드**를 넣어요. 그다음 설치가 끝났는지 브라우저와 서버 화면으로 확인해요.

## 준비물

- 4장에서 메모한 서버의 **`PublicIp`** (예: `3.38.12.34`)
- 도메인을 관리하는 곳(Cloudflare, 가비아, 후이즈, 카페24, Route 53 등)의 로그인 정보
- 10분 + 반영을 기다리는 시간 (몇 분에서 1시간)

## 먼저 알아 두기: 어떤 레코드를 넣나요

도메인 모양에 따라 넣는 줄 수가 달라요.

| 내 도메인 모양 | 넣을 A 레코드 |
|---|---|
| 앞부분이 없는 도메인 (예: `example.co.kr`) | 두 줄: 이름 `@` 와 이름 `www`, 값은 둘 다 `PublicIp` |
| 앞부분이 있는 도메인 (예: `app.example.co.kr`) | 한 줄: 이름 `app`, 값은 `PublicIp` |

- `www` 로 들어온 손님은 서버가 자동으로 `https://example.co.kr` 로 옮겨 줘요. `www` 줄이 없어도 설치와 HTTPS 에는 문제가 없어요.
- 루트 도메인 이름 칸은 업체마다 `@`, 빈칸, 또는 도메인 이름 그대로를 써요.

## 5.1 Route 53 을 쓰는 경우

4장 명령에 `--hosted-zone-id` 를 붙였다면 `example.co.kr`(4장에 넣은 도메인)의 A 레코드는 **자동으로 만들어졌어요.**

1. AWS 화면 위 검색창에 **Route 53** 을 입력해 열어요.
2. **호스팅 영역** 을 누르고 내 도메인을 눌러요.
3. 4장에 넣은 도메인의 A 레코드가 `PublicIp` 를 가리키는지 확인해요.
4. 앞부분이 없는 도메인이라면 **레코드 생성** 을 눌러 `www` A 레코드를 같은 IP 로 하나 더 만들어요.

**이렇게 보이면 성공:** 레코드 목록에 A 레코드가 있고, 값이 `PublicIp` 와 같아요.

`--hosted-zone-id` 를 붙이지 않았다면 아래 5.2 나 5.3 처럼 직접 넣어요.

## 5.2 Cloudflare 를 쓰는 경우

> **참고** Cloudflare 화면은 영어로 나오는 경우가 많아서 영어 이름을 적었어요.

1. https://dash.cloudflare.com 에 로그인해요.
2. 내 도메인을 눌러요.
3. 왼쪽 메뉴에서 **DNS** > **Records** 를 눌러요.
4. **Add record** 를 눌러요.
5. **Type** 에서 `A` 를 골라요.
6. **Name** 에 `@` 를 입력해요 (앞부분이 있는 도메인이면 `app` 처럼 그 앞부분).
7. **IPv4 address** 에 `PublicIp` 를 붙여 넣어요.
8. **Proxy status** 스위치를 눌러 **회색 구름 (DNS only)** 으로 바꿔요. 주황색이면 안 돼요.
9. **TTL** 은 `Auto` 그대로 둬요.
10. **Save** 를 눌러요.
11. 앞부분이 없는 도메인이면 4–10 을 한 번 더 해요. 이번에는 **Name** 에 `www` 를 넣어요.

![Cloudflare A 레코드 추가: DNS only (회색 구름)](../img/ko/cloudflare-dns-a-record.png)

**이렇게 보이면 성공:** Records 목록에 A 레코드가 보이고, Proxy status 칸이 **DNS only** (회색 구름)예요.

> **주의** **주황색 구름(Proxied)** 을 켜면 서버가 보안 인증서(HTTPS)를 받지 못해요. 다해 서버는 인증서를 직접 받고, 고객 연결도 직접 받아요. 꼭 **회색 구름 (DNS only)** 으로 두세요.

## 5.3 가비아, 후이즈, 카페24 같은 다른 업체를 쓰는 경우

메뉴 이름은 업체마다 달라요. **"DNS 관리"** 나 **"DNS 설정"** 이라는 이름을 찾으세요.

1. 도메인을 산 업체 사이트에 로그인해요.
2. 내 도메인의 **DNS 관리** (또는 DNS 설정) 화면을 열어요.
3. 레코드 추가 버튼을 눌러요.
4. 형식(타입)은 **A** 를 골라요.
5. 호스트(이름)에 `@` 를 입력해요 (또는 비워 둬요. 앞부분이 있는 도메인이면 `app` 처럼).
6. 값(IP 주소)에 `PublicIp` 를 붙여 넣어요.
7. TTL 은 `300` 또는 기본값으로 둬요.
8. 저장해요.
9. 앞부분이 없는 도메인이면 호스트를 `www` 로 해서 같은 IP 로 한 줄 더 만들어요.

> **주의** 같은 이름의 **AAAA 레코드(IPv6)** 가 있고 다른 주소를 가리키면 지우세요. 남아 있으면 인증서 발급이 실패할 수 있어요.

## 5.4 기다리고 확인하기

DNS 반영에는 보통 몇 분, 길면 1시간쯤 걸려요. 그동안 서버 안 설치도 진행돼요 (4.5).

### 브라우저로 확인하기

1. 10–30분 기다려요.
2. 브라우저 주소창에 `https://example.co.kr/health` 를 입력해요 (내 도메인으로 바꿔서).
3. Enter 를 눌러요.

![브라우저에서 /health 를 연 화면](../img/ko/browser-health-ok.png)

**이렇게 보이면 성공:** 화면에 `{"ok":true` 로 시작하는 글자가 보여요 (뒤에 버전 번호가 붙어요).

4. 이번에는 주소창에 `https://example.co.kr/admin/` 을 입력해요.

**이렇게 보이면 성공:** **환영합니다! 사장님 계정을 만들어 주세요** 화면이 나와요. 설치가 끝난 거예요. 6장으로 가세요.

### DNS 가 반영됐는지 직접 보기 (선택)

1. https://dnschecker.org 를 열어요.
2. 내 도메인을 입력하고 형식을 **A** 로 골라 검색해요.
3. 결과에 `PublicIp` 가 보이면 반영된 거예요.

또는 컴퓨터에서 명령 프롬프트(Windows) 나 터미널(Mac)을 열고 `nslookup example.co.kr` 을 입력해요. 결과의 주소가 `PublicIp` 와 같으면 연결된 거예요.

## 5.5 서버 상태를 웹 화면으로 보기 (Session Manager)

`/health` 가 30분이 지나도 안 열리면 서버 안을 직접 봐요. SSH 프로그램 없이 AWS 웹 화면에서 할 수 있어요.

1. AWS 화면 위 검색창에 **EC2** 를 입력해 열어요.
2. 왼쪽에서 **인스턴스** 를 눌러요.
3. 이름이 `dahae-dahae-main` 인 서버의 왼쪽 칸을 체크해요.
4. 위쪽 **연결** 버튼을 눌러요.
5. **세션 관리자(Session Manager)** 탭을 눌러요.
6. **연결** 을 눌러요.

![EC2 인스턴스 연결: Session Manager 탭](../img/ko/aws-ssm-connect.png)

7. 새 탭에 검은 화면이 열려요. 아래 줄을 붙여 넣고 Enter 를 눌러요.

   ```
   sudo dahae status
   ```

![Session Manager 에서 sudo dahae status 를 실행한 화면](../img/ko/aws-ssm-status.png)

**이렇게 보이면 성공:** 아래처럼 `✔` 가 붙은 줄이 보여요.

```
✔ 앱 정상
✔ HTTPS 정상: https://example.co.kr/admin/
```

`!` 가 붙은 줄은 아직 할 일이에요. 설치 직후에는 아래 줄들이 `!` 로 나오는 게 정상이에요. 뒤의 장에서 하나씩 해결해요.

| `!` 줄 | 해결하는 곳 |
|---|---|
| 외부 가동 확인이 없어요 | 17장 (가동 확인) |
| 최근 외부 백업이 없어요 / 최근 사진 파일 외부 백업이 없어요 | 17장 (외부 백업) |
| 비밀 키 사본이 없어요 / 서버 밖에 보관했다는 확인이 없어요 | 6.7 (비밀 키 사본) |

8. 다 봤으면 오른쪽 위 **종료** 를 눌러 창을 닫아요.

> **팁** **연결** 버튼이 회색이거나 연결이 안 되면 인스턴스 상태가 **실행 중** 인지 보고, 2–3분 뒤 다시 해 보세요.

## 자주 생기는 문제

| 이런 일이 있으면 | 이렇게 하세요 |
|---|---|
| 브라우저에 "안전하지 않음" 이나 "연결이 비공개로 설정되어 있지 않습니다" 가 나와요 | DNS 반영 전이라 인증서가 아직 없어요. 10–30분 뒤 다시 열어 보세요 |
| `/health` 가 안 열려요 | A 레코드 값이 `PublicIp` 와 같은지, Cloudflare 라면 회색 구름인지 확인하세요. 그다음 5.5 로 상태를 보세요 |
| `sudo dahae status` 에 "HTTPS 인증서가 아직 없어요" 가 나와요 | A 레코드가 이 서버를 가리키면 몇 분 안에 자동으로 발급돼요. A 레코드를 다시 확인하세요 |
| `sudo dahae status` 에 "앱 응답 없음" 이 나와요 | 설치가 아직 진행 중일 수 있어요. 10분 뒤 다시 보세요. 계속 그러면 `sudo dahae logs` 화면을 캡처해 개발자에게 보내세요 (멈추려면 Ctrl+C) |
| `dahae: command not found` 가 나와요 | 서버 안 설치가 아직 시작 단계예요. 10분 뒤 다시 해 보세요 |
| `/admin/` 이 사장님 계정 화면이 아니라 로그인 화면이에요 | 이미 누군가 사장님 계정을 만들었어요. 개발자에게 확인하세요 |
