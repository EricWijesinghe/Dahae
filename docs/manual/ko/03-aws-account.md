# 03. AWS 담당 계정 만들기

## 이 장에서 할 일

**[사장님]** 회사 AWS 계정 안에 서버 설치만 할 수 있는 **담당 계정**(IAM 사용자) `dahae-deployer` 를 하나 만들어요. 개발자는 이 계정으로 서버를 만들어요 (4장). 회사 AWS 계정의 비밀번호는 개발자에게 주지 않아요.

이 장은 약 20–30분 걸려요. 마지막 단계(MFA 등록)는 **개발자와 통화하면서** 해요.

## 준비물

- 회사 이름으로 만든 **AWS 계정** (결제 수단 등록 완료). AWS 콘솔 주소: https://aws.amazon.com/console/
- AWS 계정에 관리자로 로그인할 수 있는 이메일과 비밀번호
- 컴퓨터 (휴대폰보다 컴퓨터가 훨씬 쉬워요)
- 비밀번호 관리 앱
- 개발자와 통화할 수 있는 시간 (마지막 단계 10분 정도)

> **참고** AWS 화면은 한국어 또는 영어로 보여요. 이 장은 한국어 화면 이름을 적었어요. AWS 가 화면 이름을 바꾸는 일이 있으니, 이름이 조금 다르면 가장 비슷한 이름을 찾으세요. 그림은 AWS 화면이라 그리지 않았고 자리만 표시했어요.

## 이 장에서 만드는 것

| 이름 | 종류 | 하는 일 |
|---|---|---|
| `dahae-boundary` | 정책 (권한 한도) | 서버가 쓰는 역할들이 이 한도 안에서만 움직이게 해요. **아무에게도 붙이지 않아요** |
| `dahae-deployer-policy` | 정책 | 담당 계정이 할 수 있는 일(다해 서버 만들기)을 정해요 |
| `dahae-deployer` | 사용자 (담당 계정) | 개발자가 로그인할 계정이에요 |

> **주의** 정책 이름은 **글자 하나까지 똑같이** 써야 해요. 특히 `dahae-boundary` 이름이 다르면 4장의 서버 만들기가 실패해요.

## 3.1 AWS 에 로그인하고 지역을 서울로 바꾸기

1. 컴퓨터 브라우저에서 https://aws.amazon.com/console/ 을 열어요.
2. 회사 AWS 계정으로 로그인해요.
3. 화면 **오른쪽 위**에 지역 이름(예: "버지니아 북부")이 보여요. 그것을 눌러요.
4. 목록에서 **아시아 태평양(서울) ap-northeast-2** 를 눌러요.

![AWS 지역 메뉴에서 서울 선택](../img/ko/aws-region-seoul.png)

**이렇게 보이면 성공:** 오른쪽 위에 **서울** 이라고 보여요.

> **주의** 이 장과 4장의 모든 일은 **서울** 지역에서 해요. 다른 지역에서 하면 서버가 다른 나라에 만들어져요.

## 3.2 정책 두 개 만들기 (빠른 방법: 명령 한 줄)

AWS 화면 안에 있는 **CloudShell**(검은 명령 화면)에 한 줄을 붙여 넣으면 정책 두 개가 한 번에 만들어져요. 이 방법을 권장해요. CloudShell 을 쓸 수 없을 때만 3.3 의 손으로 하는 방법을 쓰세요.

1. 화면 위쪽 막대에서 **CloudShell** 아이콘(`>_` 모양)을 눌러요. 검색창 오른쪽 근처에 있어요.
2. 화면 아래쪽(또는 새 탭)에 검은 화면이 열려요. 처음 열면 준비에 1–2분 걸릴 수 있어요. 글자를 입력할 수 있는 줄(`$` 표시)이 나올 때까지 기다려요.
3. 아래 한 줄을 **통째로** 복사해요.

   ```
   curl -fsSL https://raw.githubusercontent.com/EricWijesinghe/Dahae/master/deploy/aws/launch.sh | bash -s -- --admin
   ```

4. CloudShell 검은 화면을 한 번 눌러요.
5. 붙여 넣어요 (Windows: **Ctrl+Shift+V** 또는 마우스 오른쪽 버튼 > **붙여넣기**, Mac: **Cmd+V**).
6. 키보드의 **Enter** 를 눌러요.
7. 몇 초 기다려요.

![CloudShell 에서 정책 만들기 명령을 실행한 화면](../img/ko/aws-cloudshell-admin.png)

**이렇게 보이면 성공:** 아래 세 줄이 보여요.

```
created policy dahae-boundary
created policy dahae-deployer-policy
Next: IAM > Users > the deployer's user > attach dahae-deployer-policy and AWSCloudShellFullAccess (not dahae-boundary).
```

- 한 번 더 실행했거나 전에 만든 적이 있으면 `created` 대신 `policy dahae-boundary already exists` 처럼 나와요. 이것도 성공이에요.
- 정책을 만들었으면 3.3 은 건너뛰고 **3.4** 로 가세요.

## 3.3 정책 두 개 만들기 (손으로 하는 방법)

> 3.2 를 끝냈다면 이 절은 건너뛰세요.

정책 내용(JSON)은 개발자에게 받거나, 다해 저장소의 `deploy/aws/dahae-boundary-policy.json` 과 `deploy/aws/deployer-iam-policy.json` 파일에서 복사해요.

### 권한 한도 정책 `dahae-boundary`

1. 화면 위 검색창에 **IAM** 을 입력하고 **IAM** 을 눌러요.
2. 왼쪽 메뉴에서 **정책** 을 눌러요.
3. **정책 생성** 을 눌러요.
4. **JSON** 을 눌러요.
5. 입력 칸의 글자를 모두 지우고, `dahae-boundary-policy.json` 의 내용을 **전부** 붙여 넣어요.
6. **다음** 을 눌러요.
7. 정책 이름에 정확히 `dahae-boundary` 를 입력해요.
8. **정책 생성** 을 눌러요.

### 담당 계정 정책 `dahae-deployer-policy`

1. 다시 **정책 > 정책 생성 > JSON** 을 눌러요.
2. 입력 칸의 글자를 모두 지우고, `deployer-iam-policy.json` 의 내용을 **전부** 붙여 넣어요.
3. **다음** 을 눌러요.
4. 정책 이름에 정확히 `dahae-deployer-policy` 를 입력해요.
5. **정책 생성** 을 눌러요.

**이렇게 보이면 성공:** **정책** 목록에서 `dahae` 로 검색하면 `dahae-boundary` 와 `dahae-deployer-policy` 두 개가 보여요.

## 3.4 담당 계정(IAM 사용자) 만들기

1. 화면 위 검색창에 **IAM** 을 입력하고 **IAM** 을 눌러요.
2. 왼쪽 메뉴에서 **사용자** 를 눌러요.
3. **사용자 생성** 을 눌러요.
4. **사용자 이름** 칸에 `dahae-deployer` 를 입력해요.
5. **AWS Management Console 에 대한 사용자 액세스 권한 제공** 을 체크해요.
6. 암호는 **사용자 지정 암호** 를 골라요.
7. 강한 암호를 만들어 입력해요. 비밀번호 관리 앱으로 만들면 편해요. 바로 비밀번호 관리 앱에 저장하세요.
8. "다음 로그인 시 암호 재설정 필요" 는 체크해도 되고 해제해도 돼요.
9. **다음** 을 눌러요.

![IAM 사용자 만들기 화면](../img/ko/aws-iam-create-user.png)

## 3.5 담당 계정에 정책 붙이기

1. **권한 설정** 화면에서 **직접 정책 연결** 을 골라요.
2. 정책 목록 위의 검색 칸에 `dahae-deployer-policy` 를 입력해요.
3. `dahae-deployer-policy` 왼쪽 칸을 체크해요.
4. 검색 칸을 지우고 `AWSCloudShellFullAccess` 를 입력해요.
5. `AWSCloudShellFullAccess` 왼쪽 칸을 체크해요. (4장의 명령 한 줄에 필요해요.)
6. `dahae-boundary` 는 **체크하지 마세요.**
7. **다음** 을 눌러요.
8. 확인 화면에서 **사용자 생성** 을 눌러요.

![정책 직접 연결: 두 개만 체크](../img/ko/aws-iam-attach-policies.png)

**이렇게 보이면 성공:** 사용자 목록에 `dahae-deployer` 가 보여요. 사용자를 누르면 **권한** 탭에 `dahae-deployer-policy` 와 `AWSCloudShellFullAccess` 두 개만 있어요.

> **주의** 액세스 키(Access key)는 **만들지 마세요.** 다해는 키 없이 임시 권한으로 동작해요.

## 3.6 MFA(2단계 인증) 등록하기 — 개발자와 통화하며

담당 계정의 정책은 스스로 MFA 를 등록할 수 없게 되어 있어요. 그래서 사장님이 등록해 줘야 해요. 인증 앱은 **개발자 휴대폰**에 들어가요.

1. **개발자에게 전화**해요. 통화를 끊지 마세요.
2. IAM 의 **사용자** 목록에서 `dahae-deployer` 를 눌러요.
3. **보안 자격 증명** 탭을 눌러요.
4. **다단계 인증(MFA) 할당** 을 눌러요.
5. MFA 장치 이름을 입력해요 (예: `developer-phone`). 이름 칸이 없으면 넘어가요.
6. **인증 앱** 을 골라요.
7. **다음** 을 눌러요.
8. **QR 코드 표시** 를 눌러요. 화면에 QR 코드가 나와요.
9. 개발자에게 "QR 코드를 보여 줄게요" 라고 말하고, 화면 공유나 영상 통화로 개발자가 자기 휴대폰 인증 앱으로 QR 코드를 읽게 해요.
10. 개발자가 인증 앱에 보이는 **6자리 숫자**를 불러 줘요. **MFA 코드 1** 칸에 입력해요.
11. 숫자가 바뀌면(30초쯤 뒤) 개발자가 **다음 6자리 숫자**를 불러 줘요. **MFA 코드 2** 칸에 입력해요.
12. **MFA 추가** 를 눌러요.

![MFA 장치 할당 화면 (QR 은 가렸어요)](../img/ko/aws-iam-mfa.png)

**이렇게 보이면 성공:** **보안 자격 증명** 탭의 **다단계 인증(MFA)** 목록에 장치 하나가 보여요.

> **참고** MFA 를 켜기 전에는 이 계정으로 서버 관련 작업을 하면 거부돼요. 정책이 그렇게 막고 있어요. 고장이 아니에요.

## 3.7 개발자에게 계정 정보 전달하기

1. AWS 화면 오른쪽 위의 계정 이름을 눌러요.
2. **계정 ID**(12자리 숫자)를 확인해요.
3. 아래 세 가지를 개발자에게 전해요. **비밀번호는 다른 경로로 따로** 보내요.

| 보낼 것 | 예시 | 보내는 방법 |
|---|---|---|
| 로그인 주소 | `https://123456789012.signin.aws.amazon.com/console` (가운데 숫자 = 계정 ID) | 메시지 가능 |
| 사용자 이름 | `dahae-deployer` | 메시지 가능 |
| 비밀번호 | (3.4 에서 만든 암호) | 전화로 불러 주기, 또는 비밀번호 관리 앱 공유. **채팅 금지** |

MFA 는 3.6 에서 이미 개발자 휴대폰에 설정됐어요.

**이렇게 보이면 성공:** 개발자가 담당 계정으로 로그인하고 MFA 코드까지 넣어 들어갔다고 알려 줘요.

## 자주 생기는 문제

| 이런 일이 있으면 | 이렇게 하세요 |
|---|---|
| CloudShell 아이콘이 안 보여요 | 지역이 서울인지 확인하세요. 화면이 좁으면 아이콘이 숨을 수 있어요. 브라우저 창을 넓히거나, 검색창에 **CloudShell** 을 입력해 여세요 |
| CloudShell 에서 `AccessDenied` 가 나와요 | 회사 계정의 관리자로 로그인했는지 확인하세요. 권한이 적은 사용자로는 정책을 만들 수 없어요 |
| 붙여 넣었는데 아무 일도 없어요 | **Enter** 를 눌렀는지 확인하세요. 줄 전체가 한 줄로 붙었는지도 보세요 |
| 정책 이름을 잘못 썼어요 | **정책** 목록에서 잘못 만든 정책을 지우고, 정확한 이름으로 다시 만드세요 |
| `dahae-boundary` 를 사용자에게 붙였어요 | 사용자 > **권한** 탭에서 `dahae-boundary` 를 **제거** 하세요 |
| MFA 코드를 넣었는데 실패해요 | 개발자 휴대폰의 시간이 자동 설정인지 확인하고, 연속된 두 숫자를 다시 받아 넣으세요 |
| 개발자가 로그인은 되는데 아무것도 못 해요 | MFA 를 등록했는지 확인하세요 (3.6). MFA 없이는 정책이 막아요 |
