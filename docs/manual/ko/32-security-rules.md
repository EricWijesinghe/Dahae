# 32. 보안 수칙

**이 장에서 할 일:** 고객 정보와 돈을 지키기 위해 사장님과 직원이 꼭 지킬 규칙을 알아요. 규칙은 짧지만 하나라도 빠지면 사고가 날 수 있어요. 직원에게도 이 장을 꼭 읽게 하세요.

> **준비물**
>
> - 비밀번호 관리 앱. 어떤 앱을 쓸지는 회사가 정해요.
> - 휴대폰 화면 잠금 (비밀번호나 지문).
> - 복구 코드를 적은 종이를 넣어 둘 안전한 곳 (금고, 잠기는 서랍).

---

## 32.1 비밀 값은 채팅에 쓰지 않아요

비밀 값이란 비밀번호, 결제·문자 키, 웹훅 시크릿, 복구 코드, 설치 코드, 비밀 키 사본과 그 잠금 비밀번호예요.

1. 비밀 값은 **카카오톡, 문자, 이메일 본문, 문서**에 쓰지 않아요.
2. 비밀 값은 **비밀번호 관리 앱**에 저장해요.
3. 다른 사람에게 꼭 전해야 하면 **전화**처럼 기록이 남지 않는 방법을 써요. 아이디와 비밀번호는 서로 다른 방법으로 보내요 (예: 아이디는 메일, 비밀번호는 전화).
4. 결제·문자 키는 회사 사이트에서 복사해 **콘솔 [설정] 카드에 바로 붙여넣어요.** 중간에 메모장이나 채팅에 남기지 않아요. 붙여넣은 뒤 메모장 내용은 지워요.
5. 화면을 캡처해 보낼 때 키나 코드가 보이면 가린 뒤 보내요.

> **팁** 콘솔에 저장한 키는 서버에서 암호화돼요. 저장한 뒤에는 화면에 `••••` 처럼 가려서만 보여요. 콘솔이 가장 안전한 보관 장소예요.

---

## 32.2 사장님 휴대폰과 인증 앱

1. **사장님 계정은 사장님이 직접 만들어요.** 설치 코드로 계정을 만든 사람의 휴대폰에 소유자 코드(인증 앱)가 생겨요. 개발자가 만들면 결제 카드를 지키는 열쇠가 개발자 휴대폰에 생겨요 (6장).
2. 소유자 인증 앱은 **사장님 휴대폰에만** 둬요. 다른 사람 휴대폰에 같은 항목을 등록하지 않아요.
3. 휴대폰에 **화면 잠금**을 꼭 걸어요.
4. 휴대폰 시간을 **자동 설정** 으로 둬요. 시간이 틀리면 코드가 안 맞아요.
5. **복구 코드 10개는 종이에 적어** 잠기는 곳에 둬요. 사진으로 찍어 휴대폰 앨범에 두지 않아요.
6. 복구 코드를 쓰거나 잃어버렸으면 바로 **[내 계정]** → **[복구 코드 다시 만들기]** 를 해요. 예전 코드는 못 쓰게 돼요 (8장).
7. 휴대폰을 바꿀 때는 **예전 휴대폰을 초기화하기 전에** 개발자와 인증 앱 옮기는 방법을 확인해요 (**확인 필요**).

> **주의** 인증 앱 코드를 누군가 전화나 메시지로 물어보면 절대 알려 주지 마세요. 다해 개발자도 사장님의 6자리 코드를 물어볼 일이 없어요.

---

## 32.3 콘솔을 쓸 때

1. **직원마다 자기 계정**을 만들어 줘요. 계정 하나를 여럿이 같이 쓰지 않아요. 그래야 **[활동 기록]** 에 누가 했는지 남아요 (20장, 23장).
2. 권한은 필요한 만큼만 줘요. 예약과 상담만 하는 직원은 **상담원**, 설정까지 바꿔야 하는 사람만 **관리자** 예요.
3. 개발자에게 관리자 계정이 필요하면 **[직원]** 에서 따로 만들어 줘요. 일이 끝나면 **[비활성화]** 해요.
4. 여러 사람이 쓰는 PC 에서는 일을 마치면 **[로그아웃]** 해요.
5. 저장한 설정 카드는 저절로 잠겨요. 잠금 해제는 소유자만 할 수 있어요. 잠금을 풀었다면 일이 끝나는 대로 **[잠그기]** 로 바로 잠가요. 그냥 두어도 5분 뒤 저절로 잠겨요 (9장).
6. 돈이나 개인정보를 다루는 일(지급, 계좌 보기, 고객 자료 사본, 탈퇴 처리)은 인증 앱 코드를 한 번 더 물어봐요. 귀찮아도 정상이에요. 그 사람이 정말 본인인지 확인하는 장치예요.
7. 파트너 계좌나 주민등록번호처럼 민감한 값은 **볼 때마다 기록**이 남아요. 꼭 필요할 때만 열어요 (20장, 21장).

---

## 32.4 AWS 를 쓴다면

1. AWS **액세스 키(장기 키)는 만들지 않아요.** 서버 배포는 키 없이 임시 권한으로 돌아가요 (3장).
2. 개발자용 AWS 계정(`dahae-deployer`)에는 **MFA** 를 꼭 걸어요 (3장).
3. 권한 한도 정책 `dahae-boundary` 는 만들기만 하고 **누구에게도 붙이지 않아요** (3장).
4. AWS 루트(처음 가입한) 계정은 평소에 쓰지 않아요. 루트 계정에도 MFA 를 걸어요.
5. AWS 로그인 정보는 비밀번호 관리 앱에 두고, 32.1처럼 전해요.

---

## 32.5 직원이 그만둘 때

31장 31.7 체크리스트를 그날 바로 해요.

1. **[직원]** 에서 **[비활성화]** 해요.
2. 그 사람이 소유자였다면 먼저 **[소유자 넘기기]** 를 해요. 소유자 계정은 끌 수 없어요.
3. 그 사람이 알던 회사 서비스 비밀번호를 바꿔요.
4. 그 사람이 키를 다뤘다면 키를 새로 발급해 **[설정]** 에 넣어요.

---

## 32.6 고객 개인정보

1. 고객이 자기 정보를 요청하면 **가입된 전화번호로 본인인지 먼저 확인**해요 (23장).
2. **[탈퇴·개인정보 요청]** 에서 받은 자료 사본 파일은 **그 고객에게만** 전해요. 다른 사람에게 보내거나 PC 에 오래 두지 않아요. 전한 뒤에는 PC 에서 지워요.
3. 고객 전화번호나 주소를 개인 휴대폰 연락처에 저장하지 않아요.
4. 탈퇴 처리는 되돌릴 수 없어요. 고객에게 한 번 더 확인한 뒤 실행해요.
5. 파트너(기사님)의 탈퇴와 자료 사본은 아직 콘솔에서 할 수 없어요. 개발자에게 보내요.

---

## 32.7 서버

1. 서버의 `.env` 파일은 **손으로 고치지 않아요.** 잘못 고치면 모든 연동이 멈춰요.
2. 서버의 `DATA_KEY` 는 **바꾸지 않아요.** 저장된 키와 외부 백업을 열 수 없게 돼요. 바꿔야 하면 개발자가 해요.
3. 서버 접속 권한(AWS 계정, 서버 회사 계정)은 사장님과 개발자만 가져요.
4. 매주 자동 업데이트를 끄지 않아요. 보안 수정도 업데이트로 들어와요. 안정(stable) 채널과 베타 채널의 최신 버전만 보안 수정을 받아요.
5. 비밀 키 사본과 잠금 비밀번호는 서로 다른 곳에 둬요 (27장).

---

## 32.8 서버가 대신 해 주는 일

사장님이 따로 하지 않아도 서버와 설치 프로그램이 이렇게 지켜요.

- 직원 로그인에는 비밀번호와 인증 앱 코드가 함께 필요해요. 이 2단계 인증은 끌 수 없어요.
- 비밀번호나 코드를 여러 번 틀리면 계정이 잠깐 잠기고, **계정 보안 이상(로그인 잠금 등)** 알림이 가요.
- 콘솔에 저장한 키, 파트너 계좌 같은 값은 암호화해서 저장해요.
- **[활동 기록]** 과 동의 기록은 수정하거나 지울 수 없어요.
- 보관 기간이 지난 개인정보는 자동으로 지워요.
- 서버에는 자동 보안 업데이트와 SSH 침입 차단(fail2ban)이 설치돼요. 서버 방화벽(22, 80, 443만 열기)은 AWS 설치에서는 자동으로 켜지고, 다른 클라우드에서는 설치할 때 물어봐요 (처음 답은 "아니요" 예요). 켜지 않았다면 클라우드 화면의 방화벽에서 22, 80, 443 만 열어 두세요 (7장).
- 백업은 암호화돼요.

---

## 32.9 사고가 의심되면

29장 29.9의 순서를 바로 따라 해요. 그리고 **반드시 개발자에게 연락**해요.

## 32.10 프로그램의 보안 문제를 발견하면

다해 프로그램 자체의 보안 약점을 발견했다면 **공개 게시판이나 채팅에 올리지 마세요.** 다해 저장소의 `SECURITY.md` 에 적힌 비공개 신고 방법(GitHub **Security → Report a vulnerability**)으로 알려 주세요. 고객 데이터는 신고에 넣지 마세요.

---

## 자주 생기는 문제

> **자주 생기는 문제**
>
> - **직원이 키를 채팅으로 보냈어요** → 그 키는 샌 것으로 보고, 회사 사이트에서 새로 발급해 **[설정]** 에 넣은 뒤 옛 키를 폐기하세요 (29.9).
> - **복구 코드 종이를 잃어버렸어요** → 바로 **[내 계정]** → **[복구 코드 다시 만들기]** 를 하세요.
> - **누가 인증 코드를 알려 달래요** → 알려 주지 말고 개발자에게 알리세요.
> - **공용 PC 에서 로그아웃을 안 했어요** → **[내 계정]** → **[모든 기기에서 로그아웃]** 을 누르세요.
